# 系统设计报告

## 1. 架构

系统采用分层架构：

```text
React 前端
    |
REST API
    |
FastAPI 路由层
    |
服务层
    |
SQLAlchemy ORM
    |
PostgreSQL / SQLite（开发）
```

Redis 预留用于缓存会话、热点分析结果以及限流计数器。

## 2. 主要模块

- 认证模块
- 商品与分类模块
- 订单模块
- 事件日志模块
- 数据分析模块
- 推荐系统模块
- 管理控制模块

## 3. 数据库设计

### 核心实体

- `users`
- `categories`
- `products`
- `orders`
- `order_items`
- `event_logs`

### 规范化说明

数据库模式遵循第三范式（3NF）：

- 用户、商品、分类和订单数据按职责拆分；
- 订单项通过数量与单价保存商品快照；
- 事件日志将行为轨迹与交易数据分离存储。

## 4. ER 摘要

```text
User 1 --- n Order 1 --- n OrderItem n --- 1 Product n --- 1 Category
User 1 --- n EventLog
```

## 5. 大数据方案

事件表作为采集层，用于记录：

- 登录行为
- 浏览行为
- 购买行为
- 内部操作行为

分析服务将关系型记录转换为 Pandas DataFrame，用于实现：

- 热销商品聚合
- 滚动趋势分析
- 异常检测
- 用户分层
- 协同过滤

## 6. 风险评估

### 技术风险

- 数据稀疏会削弱推荐质量；
- 在早期阶段，预测精度会有限；
- SQLite 与 PostgreSQL 的差异会影响本地与生产一致性。

### 项目管理预案

- 保持分析算法模块化、可替换；
- 在稀疏数据场景下提供兜底推荐；
- 使用环境变量驱动数据库配置；
- 在前端联调前冻结 API 合约。
